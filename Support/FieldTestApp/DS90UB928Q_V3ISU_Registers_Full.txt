SlaveID0             0x60
;  1  7  Unsigned  SlaveDevice0ID         I2C address of the remote slave device 0 attached to the remote serializer
;  0  1  Unsigned  Reserved               this bit is reserved

; In order to cause the 928 to convince an attached 925 to act as an I2C proxy
; for an I2C transaction originating on the 928 side but targeting an
; I2C slave on the 925 side (other than the 925 itself) you MUST employ one pair
; of the 928's SlaveIDx and SlaveAliasx registers. For example, assume the remote
; 925 has the default 7-bit slave dev address 0x0C (which TI's literature often
; writes as the 8-bit address 0x18). Furthermore, assume that you need to cause
; this remote 925 to communicate with an I2C device having the 7-bit slave dev
; address 0x30 (which is the 8-bit addr 0x60). To accomplish this you must
; initialize the 928's SlaveID0 reg with the 8-bit address 0x60. This SlaveID0
; reg holds the I2C address that will ultimately be employed on the remote end
; of the FPD-Link III cable. Furthermore you must initialize the 928's SlaveAlias0 
; reg with an arbitrary (8-bit) address X not already claimed on the local bus.
; It is acceptable to use the same value as was just put in the SlaveID0 register.
; You then initiate a transaction on the 928's SCL/SDA pins that targets the
; address X held in the SlaveAlias0 register. This will cause the 928 to cause
; the 925 to recreate this same transaction on the far side of the cable but
; with the remapped I2C slave dev address taken from the value in the 928's
; SlaveID0 reg (i.e. the 7-bit address 0x30).

; This need to employ the SlaveAlias register is explained in TI document
; SNLA222 entitled "I2C Over DS90UB913/4 FPD-Link III With Bidirectional
; Control Channel". Furthermore the 928's Configuration1 reg (at offset addr 3)
; must have the "I2C Pass Thru" bit set. [There is also an I2C "Pass Thru All" bit
; in the I2cControl1 reg at offset addr 5 but you don't want that -- see TI SNLA222.]
; Note that you don't need to employ the 928 (or 925) SlaveIDx and SlaveAliasx
; registers in order to convince the local 928 to communicate with the remote 925.
