; This file describes the registers in the T.I. DS90UB926Q deserializer.
; These registers (and their subfields) are described in Section 7.6 of the datasheet.

; The contents of this file are parsed by my cTreeViewBox class.
; A semi-colon indicates a comment line.
; The format of the non-indendented lines is:
; RegName  RegAddr  RW/RO DefValue
; The format of the indendented lines is:
; LSBit   NumBits  Unsigned/Signed  FieldName  PopUpToolTip(optional)
; where blanks (space characters) separate these 5 fields.
; The PopUpToolTip includes the remainder of the line and hence can include blanks.
; The PopUpToolTip can be made multiline by including the 2 char sequence "\n".
; LSBit counts from 0.
; Values can be expressed in hex if preceded by 0x or 0X.

  7  1  Unsigned  RemoteAutoPowerDown  power down when no forward channel link is detected
  3  4  Unsigned  Reserved             these bits are reserved
  2  1  Unsigned  BackChannelEnable    enables the back channel
  1  1  Unsigned  DigitalReset1        resets the entire digital block including the registers
  0  1  Unsigned  DigitalReset0        resets the entire digital block except for the registers

Configuration0           2  RW  8 0x80
  7  1  Unsigned  OutputEnable                 enable LVCMOS outputs
  6  1  Unsigned  OenAndOssSelOverride         override OEN and OSS_SEL pin
  5  1  Unsigned  OscClockEnable               enable OSC clock being output onto PCLK when LOCK is low
  4  1  Unsigned  OutputSleepStateSelect       enable OSS_SEL to control output state when LOCK is low
  3  1  Unsigned  BackwardCompatibilitySelect  if 1 backward compatibility mode is set by register, if 0 by MODE_SEL pin
  2  1  Unsigned  BackwardCompatibilityMode    be backward compatible with DS90UR907Q
  1  1  Unsigned  LfModeSelect                 if 1 frequency range is set by register, if 0 by LFMODE (accomplished with MODE_SEL pin)
  0  1  Unsigned  LfMode                       if 1 PCLK range 5-15 MHz, if 0 15-85 MHz
; The 926 chip's power-on default for this reg is 0x00 but we want to enable the LVCMOS outputs.
; If PCLK is between 5-15 MHz then you will also want to set the LFMODE bit.

; The LFMode must be selected when PCLK < 15 MHz. LFMode can be
; selected either via the Configuration1 register or via the
; MODE_SEL pin.  The advantage of using MODE_SEL is that
; "When LFMODE is changed a PDB reset is required".

Configuration1           3  RW  8 0xF9
  7  1  Unsigned  Reserved               this bit is reserved
  6  1  Unsigned  CrcGeneratorEnable     enable back channel CRC generator
  5  1  Unsigned  Reserved               this bit is reserved
  4  1  Unsigned  FilterEnable           enable filter that rejects HS, VS, or DE pulses narrower than 2 PCLKs
  3  1  Unsigned  I2cPassThruMode        enable I2C pass-through mode
  2  1  Unsigned  AutoACK                enable auto acknowledge
  1  1  Unsigned  Reserved               this bit is reserved
  0  1  Unsigned  PixelClockEdgeSelect   parallel interface is strobed on the rising clock edge
; The 926 chip's power-on default for this reg is 0xF0 but we want to enable I2C pass-through.
; Assuming this Configuration1 register is initialized to 0xF8 then the 926 deserializer chip
; will begin to acts as an I2C proxy and allow I2C transactions originating on its I2C bus to reach
; the I2C bus (and hence the 925 serializer) on the far end of the FPD-Link III interconnect cable.

RemoteDeviceID             7  RO  8 0x18
  1  7  Unsigned  SerializerDeviceID     I2C address of the remote serializer
  0  1  Unsigned  SerDeviceIdFrozen      prevents autoloading of I2C address of remote serializer
; This reg is actually writable but I mark it read-only so that the serializer I2C address received
; by the 926 deserializer through the communication link is not disturbed.
; The 926 chip's power-up default for this reg is 0x00. However this register
; gets loaded automatically based upon the 2-way communication between the 925 serializer
; and the 926 deserializer.

; TI's AnalogLaunchPAD app says this reg is named "RemoteDeviceID"
; However I prefer "SerializerID" to be symmetric with the DeserializerID reg name in the 925.
